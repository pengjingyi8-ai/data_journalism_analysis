# 小红书数据采集方法说明

## 一、采集工具

- **联网采集**：使用开源工具 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)（GitHub，Python）。
  - 选择原因：小红书设有请求签名与风控机制，从零实现签名与登录成本高、易触发验证码；该工具已实现签名、CDP 复用浏览器登录态、评论翻页等能力。
  - 登录方式：**二维码扫码登录小号**（`LOGIN_TYPE=qrcode`），通过 CDP 模式复用本机 Chrome，不输入主账号密码。
- **自行编写的代码**（见同目录）：
  - `crawler.py`：把 MediaCrawler 输出的 CSV 转换为《统一规范》要求的 `raw.csv`（字段映射、时间窗过滤、按 `note_id`/`comment_id` 去重、`source_type` 分类、去除 `post_url` 中的 `xsec_token`）。
  - `clean.py`：`raw.csv` → `processed.csv`（去重、去空/纯符号/广告/明显无关内容、jieba 分词、生成质量报告）。

## 二、采集配置（MediaCrawler）

- 平台：`xhs`（小红书）；采集类型：`search`（关键词搜索）
- 排序：`SORT_TYPE = general`（综合排序）
- 每关键词抓取笔记数：`CRAWLER_MAX_NOTES_COUNT`
- 每帖评论上限：`CRAWLER_MAX_COMMENTS_COUNT_SINGLENOTES`（含子回复）
- 数据保存：CSV（`output/media_crawler/xhs/csv/`）

## 三、关键词分层策略

只用"后会友期"一词会召回大量 CP/追星噪声，因此按议题分层（详见 `docs/keyword_plan.md`）：

| 层 | 示例 |
|---|---|
| 议题锚点（主力） | 后会友期 和解 / 绝交 / 断联 / 复合 / 原谅 / 不原谅 / 没必要 |
| 嘉宾 × 议题 | 后会友期 许飞 / 厉娜 / 白小纯 / 青稚 / 马天宇 / 张萌 / 文吉儿 / 王子璇 |
| 泛话题（补友情观） | 朋友绝交 / 该不该和好 / 友情内耗 |
| 节目锚点 | 后会友期（仅用于找官方/嘉宾账号） |

## 四、帖子级过滤

排除纯 CP/星座/追星/八卦、营销引流、明显无关的帖子，排除的帖子 ID 记录于 `docs/exclude_posts.txt`。

## 五、合规与隐私

- 使用小号二维码登录，不采集私信、手机号、真实姓名、IP 归属地等个人信息；
- `user_id` 为 MediaCrawler 脱敏后的 `creator_hash`，不含原始用户 ID；
- 控制采集频率，遇验证码人工通过；不做验证码破解、不挂代理池、不夜间大规模采集；
- 数据仅用于课程研究，不公开、不商用。

## 六、可复现性

- 原始抓取结果保留在 `output/media_crawler/xhs/csv/`；
- 清洗删除项以 `comment_id` 清单保存（`docs/exclude_comments.txt`），重跑 `clean.py` 结果一致。

> 说明：由于平台风控，本次采集中途出现接口限流中断，已抓取数据完整落盘并纳入交付；未采用任何绕过风控的手段。

## 七、实际操作过程

### 1. 采集

1. 先用单个词「后会友期」做试点，发现召回的多是 CP、追星、星座类帖子，评论区偏题严重。据此调整：**主力改用"议题锚点词"**（和解/绝交/断联/复合/原谅/不原谅/没必要等），并补充嘉宾名、泛友情话题。
2. 按关键词分批采集，每批约 6–14 个词，每词抓取若干篇笔记及其评论（含子回复）。
3. 采集通过小号二维码登录，复用本机浏览器登录态；遇到接口限流/验证码时暂停，**不强行连续请求**。
4. 原始抓取结果（CSV）保留在 `output/media_crawler/xhs/csv/`。

### 2. 转换为规范字段

- 用 `crawler.py` 把原始 CSV 转换成 `raw.csv`：字段映射、按帖子发布时间与评论发布时间双重时间窗过滤、按 `note_id`/`comment_id` 去重、`source_type` 分类、去除帖子链接里的访问令牌。

### 3. 清洗与筛选

1. 用 `clean.py` 做基础清洗：按 `comment_id` 与「帖子+用户+文本」去重；删除空/纯符号/纯 URL；删除广告引流；jieba 分词写入 `tokens`。
2. **帖子级筛选**：把纯 CP/星座/追星/八卦等噪声帖写入 `docs/exclude_posts.txt` 排除。
3. **评论级筛选（人工复核）**：导出评论清单，按长度升序人工逐条查看，只把**明显无关内容**（纯附和如"是的/同意/点了"、纯语气词、纯表情、纯 @ 好友、纯笑等零信息量短评论）标记删除，标记结果以 `comment_id` 存入 `docs/exclude_comments.txt`。
4. 重跑 `clean.py` 应用删除，并剔除评论被删光的帖子，最终得到 `processed.csv` 与质量报告。
5. **未做相关性/立场判断**：一条评论表达支持还是反对和解，由 A/D 统一标注，保证两平台标注口径一致。
6. 全部删除项以 ID 清单保存，重跑结果可复现。
